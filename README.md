| Kriteria                    | Deskripsi                                                                                                                                                                                                                                                                                                                                                                                |
| :-------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Deskripsi Dataset**       | [Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud). Dataset berisi transaksi kartu kredit dengan 284.807 baris dan 31 kolom (`Time`, `Amount`, `V1` sampai `V28`, serta label `Class`).                                                                                                                                                              |
| **Masalah**                 | Transaksi fraud jumlahnya sangat sedikit dibandingkan transaksi normal. Dari seluruh data, terdapat 492 transaksi fraud dan 284.315 transaksi normal (proporsi fraud hanya 0,17%). Tantangannya adalah menemukan transaksi fraud sebanyak mungkin tanpa menganggap terlalu banyak transaksi normal sebagai fraud (_false positive_).                                                     |
| **Solusi machine learning** | Solusi klasifikasi biner berbasis Neural Network menggunakan TFX Pipeline. Pipeline memanfaatkan `Tuner` untuk memilih _hidden units_, _dropout_, dan _learning rate_ berdasarkan metrik PR-AUC, lalu model dideploy menggunakan **TensorFlow Serving**.                                                                                                                                 |
| **Metode pengolahan**       | Data dibaca menggunakan `CsvExampleGen`, dianalisis dengan `StatisticsGen`, dibuatkan skema menggunakan `SchemaGen`, dan diperiksa anomali dengan `ExampleValidator`. Seluruh fitur numerik dinormalisasi menggunakan _z-score_ melalui TensorFlow Transform (`Transform`). Keseimbangan kelas ditangani dengan pemberian _class weight_ 578 untuk kelas fraud dan 1 untuk kelas normal. |
| **Arsitektur model**        | Model menerima 30 fitur numerik input (`V1` sampai `V28`, `Amount`, `Time`). Input diproses oleh `Dense(64, activation='relu')`, `Dropout(0.2)`, `Dense(32, activation='relu')`, `Dropout(0.2)`, dan `Dense(1, activation='sigmoid')`. Dilatih menggunakan optimizer Adam (_learning rate_ 0,001) dan _binary cross-entropy loss_.                                                       |
| **Metrik evaluasi**         | Metrik yang digunakan adalah Recall, Precision, PR-AUC, Binary Accuracy, dan Loss yang dihitung menggunakan TFMA (TensorFlow Model Analysis). Target utama adalah memperoleh Recall minimal 0,90 agar transaksi fraud tidak terlewat.                                                                                                                                                    |
| **Performa model**          | Berdasarkan hasil evaluasi TFMA pada 95.286 data uji, model memperoleh **Recall: 0,9500**, **PR-AUC: 0,7146**, **Precision: 0,0553**, **Binary Accuracy: 0,9692**, dan **Loss: 0,1184**. Recall sebesar 0,95 berhasil melampaui target minimal 0,90.                                                                                                                                     |
| **Opsi deployment**         | Model dideploy secara independen menggunakan **TensorFlow Serving** berbasis Docker container di platform cloud Railway.                                                                                                                                                                                                                                                                 |
| **Web app**                 | Tautan endpoint metadata: `https://web-production-e377.up.railway.app/v1/models/fraud-detection/metadata`                                                                                                                                                                                                                                                                                |
| **Monitoring**              | Monitoring dilakukan menggunakan **Prometheus** dan **Grafana** yang men-scrape metrik _native_ TF Serving di path `/monitoring/prometheus/metrics`. Visualisasi pada dashboard berfokus pada metrik `:tensorflow:serving:request_count` dan latensi _request_.                                                                                                                          |
